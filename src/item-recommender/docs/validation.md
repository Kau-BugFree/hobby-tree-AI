## 확인한 동작

- 한국 시간 03:00 이상 05:00 미만 예약·수집, 05:00 직전 시간 재확인과 요청 제한 시간.
- 날짜·검색어별 중복 예약 방지, 동시 작업 선점, 임대 만료 후 복구와 오래된 작업자의 덮어쓰기 차단.
- 여러 연결에서 공유하는 분당 6회 제한. PostgreSQL은 잠금 획득 후 DB 시각을 사용하며, 호스트 시계가 61초 빠르더라도 7번째 예약을 거부함.
- 작업자의 기본 시계와 API의 만료 판단은 DB 시각 우선. DB 시각 조회 실패 시 외부 수집·상품 제공을 중단하고 민감한 예외 내용은 반환하지 않음.
- 정상 빈 검색 결과는 이전 상품을 비우고, 수집 실패는 유효한 기존 상품을 유지함. 만료 상품은 응답에서 제외하고 payload를 정리함.
- 수집 목록 등록 → 예약 → 모의 공급자 수집 → DB 저장 → 실제 HTTP 상품·구매 링크 응답.
- 숫자·문자열 가격 해석, 숫자 가격 오름차순, 가격 미확인 상품 마지막 정렬.
- Q14를 바꿔도 상품 선택·순서가 같음. 상품 1개 예산 비교만 수행하고 초과 상품도 유지함.
- 별도 상품 필터·페이지 처리·목록 버전 변경, 동의어·운영자 지정 상품 대체 경로, 빈 결과 상태 구분.
- 준비물 필요 이유 `necessityReason=null`, 내부 인증, 입력 검증, 안전한 구매 링크 검증.
- 반복 HTTP 조회는 외부 API 호출·수집 작업을 추가하지 않음.

PostgreSQL 테스트는 전용 임시 DB만 사용합니다. 실제 운영 데이터나 BE 테이블을 조회·변경하지 않았습니다. HTTP 테스트의 모의 상품은 테스트 중에만 생성되며 서비스의 실제 추천 대체 상품으로 제공되지 않습니다.

## 검증하지 않은 범위

- 애드픽 실제 API 호출, 현재 판매가·재고·구매 링크 이동·제휴 전환. 이전 실조회에서 후보가 전부 제외된 문제의 실제 응답 원인도 이번 오프라인 테스트로 해결됐다고 볼 수 없습니다. 수집 로그의 `discardReasons`로 후속 확인해야 합니다.
- 실제 운영 DB의 기존 준비물 동기화와 권한 설정.
- pg_cron 확장 설치와 자동 예약 실행. 임시 PostgreSQL에 확장이 없어 스키마·예약 SQL 함수·저장소 동작만 실제 실행했습니다.
- Docker 이미지 빌드·Compose 구동, 원격 GitHub Actions 실행, 실제 사용자 부하 성능.
- 상품 DB 보관 범위·기간의 공급자 허용. `ADPICK_STORAGE_APPROVED=false`가 기본이며 기존 필터·표시 허용과 별도 확인해야 합니다.

BE·FE 코드는 수정하지 않았습니다. 운영 적용 절차는 [배치 안내](batch.md), 남은 화면·API 연결은 [연동 계약](integration.md)을 참고하세요.
