# HobbyTree 하비 코치 음성 질문(음성→글자) 명세

FE · BE · AI 팀 공유용 | 문서 버전 1.0 | 작성일 2026-11-23

**명세 기준:** `rag 챗봇연결 v3/2026-11-09/backend/app`의 2026-11-23 코드(`transcribe.py`, `mp4_faststart.py`, `backend_bridge.py`). 활동코치 V3 API 명세(`HobbyTree_Coach_V3_API_Spec_ko.md`)의 11장과 같은 `/backend` 경로 묶음에 속합니다.

**구현 상태:** 2~4장과 7장(V3 서버)은 구현과 확인이 끝났습니다. 5장(Spring)과 6장(앱)은 아직 구현되지 않았고, 이 문서의 내용은 제안입니다. 최종 형태는 각 담당자가 정합니다.

## 1. 개요

일반 사용자가 하비 코치에 글을 쓰는 대신 말로 질문합니다. 앱이 녹음한 음성을 글자로 바꿔 입력창에 넣고, 사용자가 확인·수정한 뒤 지금과 같은 방식으로 보냅니다. 기존 채팅 경로(`POST /api/v1/coach/chat`, `POST /backend/coach/chat`)는 바뀌지 않습니다.

```
앱(녹음 ≤60초) ─ 음성 ─▶ Spring ─ 음성 ─▶ V3 ─▶ Google Speech-to-Text
앱 입력창      ◀ 글자 ── Spring ◀ 글자 ── V3
사용자가 확인·수정 후 보내기 → 기존 POST /api/v1/coach/chat
```

| 담당 | 하는 일 |
| --- | --- |
| 앱 | 마이크 권한, 60초까지 녹음, 음성 파일 업로드, 받은 글자를 입력창에 넣기 |
| Spring | 로그인 확인, 사용자별 호출 수 제한, 음성을 V3로 전달, V3의 답을 앱 응답으로 변환 |
| V3 | 음성을 구글에 보내 글자로 변환. 구글 인증 키는 V3 서버에만 있음 |

## 2. V3 경로

**POST /backend/coach/transcribe**

Spring이 서버 대 서버로 호출합니다. 토큰 검사는 `/backend/coach/chat`과 같습니다.

### 2.1 요청

| 헤더 | 값 |
| --- | --- |
| X-Coach-Service-Token | V3 서버의 `COACH_BACKEND_TOKEN`과 같은 값 |
| Content-Type | `audio/`로 시작하는 값. 예: `audio/mp4`(m4a), `audio/webm`, `audio/wav`. 대소문자와 뒤의 매개변수(`; codecs=…`)는 상관없음 |

**본문은 음성 파일의 바이트 그대로입니다.** JSON, multipart, base64가 아닙니다.

| 제한 | 값 | 넘으면 |
| --- | --- | --- |
| 크기 | 7MB(7,340,032바이트)까지 | 413 |
| 길이 | 60초까지 | 400 |

- 구글의 요청 한도 10MB는 음성이 아니라 base64로 부푼 요청 전체에 걸립니다. 8.2MB 음성은 구글이 거절했고 6.4MB 음성은 변환됐습니다. 그래서 V3는 7MB에서 먼저 막습니다. 앱 녹음(60초 m4a 약 1MB)에는 여유가 있습니다.
- 길이는 V3가 재지 않습니다. 앱이 60초에 녹음을 멈춰 지키고, 넘는 음성은 구글이 거절해 400이 됩니다.
- 사용자 ID나 대화 번호는 받지 않습니다. 이 경로는 대화 기록을 읽거나 쓰지 않습니다.

### 2.2 응답

`200`

```json
{"text": "오늘 저녁에 간단하게 만들 수 있는 요리 추천해 줘"}
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| text | string | 변환된 글자. 비어 있지 않고 앞뒤 공백이 없음. 긴 말은 구글이 나눠 준 조각을 한 칸 띄워 이어 붙인 것 |

다른 필드는 없습니다. 57초 음성의 `text`는 347자였습니다. 채팅 경로의 `message` 한도(2,000자)보다는 짧지만 앱 입력창의 500자 제한은 넘을 수 있습니다(6장).

### 2.3 오류

검사 순서는 토큰 → `Content-Type` → 크기 → 빈 본문 → 구글 호출입니다.

| HTTP 상태 | 본문 | 상황 |
| --- | --- | --- |
| 400 | 일반 텍스트 `Invalid host header` | Host 헤더가 `COACH_ALLOWED_HOSTS`에 없음 |
| 400 | `{"detail": "음성이 비어 있습니다."}` | 본문이 0바이트 |
| 400 | `{"detail": "음성을 읽을 수 없습니다. 60초 이하의 음성 파일인지 확인해 주세요."}` | 구글이 음성을 거절: 60초 초과, 알 수 없는 형식 |
| 401 | `{"detail": "X-Coach-Service-Token이 올바르지 않습니다."}` | 토큰이 없거나 다름 |
| 413 | `{"detail": "음성 파일은 7MB 이하여야 합니다."}` | 본문이 7MB를 넘음 |
| 415 | `{"detail": "Content-Type은 audio/로 시작해야 합니다."}` | 헤더가 없거나 `audio/`가 아님 |
| 422 | `{"detail": "말소리를 알아듣지 못했습니다."}` | 음성은 읽었지만 글자가 나오지 않음(무음, 소음) |
| 503 | `{"detail": "백엔드 연동 토큰(COACH_BACKEND_TOKEN)이 설정되지 않았습니다."}` | V3 서버에 토큰을 넣지 않음 |
| 503 | `{"detail": "구글 음성 인식 인증 정보(GOOGLE_APPLICATION_CREDENTIALS)가 설정되지 않았습니다."}` | V3 서버에 구글 키 파일이 없거나 읽을 수 없음 |
| 503 | `{"detail": "음성 인식 서비스를 지금 사용할 수 없습니다."}` | 구글 장애·사용량 한도·연결 실패, 구글 키의 권한 문제 |
| 504 | `{"detail": "음성 인식이 제한 시간 안에 끝나지 않았습니다."}` | 구글이 30초 안에 답하지 않음 |

- 구글 키가 폐기되거나 권한이 빠져 구글이 401·403을 줘도 V3는 503으로 답합니다. V3의 401은 `X-Coach-Service-Token` 오류에만 씁니다.
- 구글의 영어 오류 문구는 응답에 싣지 않고 V3 서버 로그에만 남깁니다.
- 구글의 400에는 V3 서버 설정 오류도 들어 있습니다(예: 그 지역에 없는 모델을 설정한 경우). 이때도 응답은 같은 400 "음성을 읽을 수 없습니다…"이고 원인은 V3 로그에 남습니다. 올바른 녹음이 계속 400이면 V3 로그를 확인합니다.

## 3. 동작 규칙

- **음성 보관:** V3는 음성을 파일이나 DB에 저장하지 않고 로그에도 남기지 않습니다. 받은 바이트는 구글 요청에만 씁니다.
- **외부 전송:** 음성은 Google Cloud Speech-to-Text v2(지역 `global`)로 전송됩니다. 개인정보 처리방침과 마이크 권한 문구에 반영할지는 팀이 정합니다.
- **재전송:** 재전송 보호가 없습니다. 같은 음성을 다시 보내면 다시 변환하고 다시 과금됩니다. 상태를 바꾸지 않는 경로라 중복 호출의 부작용은 요금뿐입니다.
- **시간:** V3는 구글 호출 전체를 30초로 제한합니다(`COACH_STT_TIMEOUT_SECONDS`). 실측은 4초 음성 1.2~1.8초, 57초 음성 9~12초입니다. Spring의 대기 시간 기본값 45초(`coach.ai.request-timeout`)면 충분합니다.
- **형식:** m4a(AAC), webm(Opus), wav를 실제 호출로 확인했습니다. 구글의 형식 자동 감지가 받는 다른 형식(mp3, ogg, flac, amr)은 확인하지 않았습니다.
- **m4a 색인 위치:** 휴대폰 녹음기는 m4a의 색인(moov)을 파일 끝에 쓰는데, 구글은 그런 파일을 읽지 못했습니다(57초 파일 9번 모두 거절). V3가 보내기 전에 색인을 앞으로 옮깁니다. 앱과 Spring은 녹음 파일을 그대로 보내면 됩니다.
- **언어:** 한국어(`ko-KR`)만 인식합니다.
- **요청 수 제한:** 이 경로에는 요청 수 제한이 없습니다. 사용자별 제한은 Spring에서 겁니다(5장).

## 4. V3 서버 설정

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| GOOGLE_APPLICATION_CREDENTIALS | 없음 | 구글 서비스 계정 키 파일(JSON)의 경로. 상대 경로는 `backend` 폴더 기준. 비우면 이 경로만 503 |
| COACH_STT_MODEL | `long` | 구글 인식 모델. `chirp_3`는 `us`·`eu` 지역에서만 됨 |
| COACH_STT_LOCATION | `global` | 구글 지역. 소문자·숫자·하이픈만 |
| COACH_STT_TIMEOUT_SECONDS | `30` | 구글 호출 제한(초, 1~115). Spring의 대기 시간보다 짧게 둠 |

- 구글 v2는 API 키를 받지 않습니다("API keys are not supported by this API"). 서비스 계정 키 파일이 필요합니다.
- 키 파일은 `.env`로 시작하는 이름(예: `backend/.env.google-credentials.json`)으로 둡니다. 그러면 `.gitignore`로 git에 올라가지 않고, 전달 전 점검(`verify_package`)이 지워야 할 파일로 알려 줍니다. 폴더를 통째로 복사하면 키 파일도 함께 나가므로 전달 전에 지웁니다.
- 의존성 `google-auth==2.63.1`이 추가됐습니다. 동봉 런타임에는 `uv pip install --python <runtime/python/python.exe> --break-system-packages google-auth==2.63.1`로 설치합니다.
- **`google-auth`가 설치되지 않은 서버는 이 경로만이 아니라 서버 전체가 시작하지 않습니다(`ModuleNotFoundError`).** 새 코드를 올리기 전에 의존성부터 설치합니다. 키 파일이 없는 경우에는 이 경로만 503이고 나머지는 그대로 동작합니다.
- 운영 V3 서버에 이 경로를 올리려면 그 서버에도 `google-auth` 설치, 키 파일 배치, `GOOGLE_APPLICATION_CREDENTIALS` 설정이 필요합니다.

## 5. Spring에 제안하는 앱용 경로

**POST /api/v1/coach/transcribe** (제안)

| 항목 | 제안 |
| --- | --- |
| 인증 | 기존 JWT |
| 요청 | `multipart/form-data`, 파일 필드 `file` |
| 응답 | 기존 `ApiResponse` 형식 안에 `text` |
| V3 호출 | 받은 파일의 바이트를 그대로 본문에 싣고, `Content-Type`은 파일 파트의 형식을 전달. 파트 형식이 없거나 `application/octet-stream`이면 m4a는 `audio/mp4` |

**V3 상태별 처리(제안):**

| V3 응답 | 뜻 | Spring 처리 |
| --- | --- | --- |
| 200 | 변환 성공 | `text` 전달 |
| 422 | 말소리 없음 | 사용자에게 "다시 말해 주세요"를 안내할 수 있는 별도 코드 |
| 400, 413, 415 | 음성 파일 문제 | 입력 오류 코드. 앱이 60초·형식을 지키면 나오지 않음 |
| 401, 토큰 503 | 연동 설정 문제 | 서버 오류. 운영자 확인 필요 |
| 그 밖의 503 | 구글 사용 불가 | 기존 `COACH503_1` |
| 504 | 시간 초과 | 기존 `COACH504_1` |

**주의할 점:**

- 기존 `CoachAiClient.chat`은 200이 아닌 응답을 429·503만 503으로, 나머지를 모두 502(`COACH502_1`)로 바꿉니다. 이 경로는 400·413·415·422를 구분해 전달해야 하므로 같은 변환을 그대로 쓰면 안 됩니다.
- 스프링 부트의 multipart 기본 한도는 파일 1MB, 요청 전체 10MB로 알고 있습니다(확인 필요). 60초 m4a(128kbps)는 약 1MB라 파일 한도에 걸릴 수 있으니 `spring.servlet.multipart.max-file-size`와 `max-request-size`를 확인해 V3 한도인 7MB에 맞추길 권합니다.
- 호출마다 구글 요금이 나갑니다. 구글은 음성 길이를 초 단위로 올림해 과금했습니다(4.08초 음성이 5초로 계산됨). 사용자별 호출 수 제한을 권합니다. 요금 단가는 확인하지 못했습니다.
- 변환된 글자는 대화 기록에 저장하지 않습니다. 사용자가 보내기를 눌러 `POST /api/v1/coach/chat`으로 올 때 평소처럼 저장됩니다.
- V3 응답은 수백 바이트라 `CoachAiClient`의 256KiB 제한 안입니다.
- V3 대기 시간은 기존 45초면 됩니다. 줄인다면 35초 이상으로 둡니다.

## 6. 앱 안내 (제안)

Expo SDK 58 기준입니다. `expo-audio` 문서를 읽고 정리했으며 앱에서 실행해 보지는 않았습니다.

- **녹음:** `expo-audio`의 `RecordingPresets.HIGH_QUALITY`를 그대로 씁니다. Android·iOS는 `.m4a`(AAC, 44.1kHz, 스테레오, 128kbps), 웹은 `audio/webm`으로 녹음됩니다. 둘 다 V3가 받습니다.
- **60초 제한:** `record({ forDuration: 60 })`으로 60초에 자동으로 멈춥니다.
- **권한과 빌드:** `app.json`의 plugins에 `expo-audio`를 넣고 `microphonePermission` 문구를 적습니다(Android는 `RECORD_AUDIO`가 기본으로 추가됨). 네이티브 모듈이 추가되므로 새 빌드가 필요합니다. 지금 `app.json`의 `"microphonePermission": false`는 `expo-image-picker`의 설정이라 별개입니다.
- **업로드:** 녹음이 끝나면 `recorder.uri`의 파일을 `FormData`에 넣어 보냅니다. 파일 형식은 `audio/mp4`(웹은 `audio/webm`)로 지정합니다.
- **결과 넣기:** 받은 `text`를 입력창에 넣고 사용자가 확인한 뒤 보내기를 누르게 합니다. 채팅 화면(`src/app/chat/conversation.tsx`)의 입력 제한은 500자(`MAX_LEN`)인데, 1분 가까이 말하면 넘을 수 있습니다. 자를지 제한을 올릴지 정해야 합니다(서버의 `message` 한도는 2,000자).
- **오류 안내:** 422는 "말소리를 알아듣지 못했어요. 다시 말해 주세요", 503·504는 "잠시 후 다시 시도해 주세요".
- **화면 표시:** 녹음 중 표시와 남은 시간을 보여 주길 권합니다.

## 7. 확인 방법과 한계

2026-11-23에 V3 앱을 임시 DB로 만들어 실제 구글 호출로 경로를 확인했습니다(구글 프로젝트의 서비스 계정, 모델 `long`, 지역 `global`). 시험 음성은 윈도우 한국어 음성 합성으로 만든 "오늘 저녁에 간단하게 만들 수 있는 요리 추천해 줘"입니다.

| 보낸 것 | 결과 |
| --- | --- |
| 4초 m4a(AAC 44.1kHz 스테레오, 색인이 파일 끝) 120회 | 모두 200, 글자가 원문과 같음, 1.2~1.8초 |
| 4초 webm(Opus) | 200, 글자가 원문과 같음, 1.2~1.4초 |
| 57초 m4a(색인이 파일 끝) 4회 | 모두 200, 같은 문장 12번이 모두 변환됨(347자), 9~12초 |
| 33초 wav(6.4MB) | 200, 7.8초 |
| 43초 wav(8.2MB) | 구글이 거절("Request payload size exceeds the limit"). 지금은 V3가 7MB에서 413으로 먼저 막음 |
| 65초 wav | 400 |
| 0.5초 무음 wav | 422 |
| 음성이 아닌 바이트(`audio/mp4`로 보냄) | 400 |

자동 테스트는 구글을 부르지 않고 가짜 응답으로 요청 형태와 오류 해석을 검증합니다(전체 1,167건 통과). 별도 검토에서 나온 지적(꾸며 낸 MP4 파일로 서버 오류나 지연을 일으킬 수 있던 점, 키 파일·구글 응답의 예외 모양)은 반영했습니다.

**확인하지 못한 것:**

- 사람 목소리, 소음이 있는 환경, 요리 용어의 인식 정확도.
- 실제 휴대폰(Android·iOS)이 녹음한 파일. 시험 m4a는 같은 형식으로 PC에서 만든 것입니다. 색인을 옮기지 못하는 구조의 파일은 구글에 그대로 가서 400이 될 수 있습니다.
- 구글 요금 단가와 무료 사용량.
- 5장과 6장의 내용(Spring과 앱은 미구현).

## 8. 남은 결정
